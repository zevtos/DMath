# Руководство по контрибьютингу

## Основные правила
1. **Не коммить в main напрямую.**  
   Все изменения — через ветки и Pull Request.

2. **Формат веток:**
   - `feature/<название>` — новая функциональность
   - `fix/<название>` — исправление ошибок
   - `chore/<описание>` — конфиги, документация, CI и т.п.
   - `test/<описание>` — тесты или демонстрационные ветки для G3.x

3. **Перед созданием PR:**
   - Прогони линтеры и форматирование  
     `npm run lint && npm run format:check` (во фронте) 
     `./gradlew check` (на бэке)
   - Убедись, что тесты проходят локально  
     `npm run test:unit` (или `./gradlew test`)
   - Проверка покрытия ≥80% (Jest или JaCoCo)

4. **Pull Request должен быть чистым:**  
   — одно изменение = одна ветка = один PR  
   — без мусорных файлов и консольных логов  

5. **Коммиты:**
   Используй понятные сообщения:

   feat: add graph visualization module
    fix: handle API error for steps[]
    chore: update CI workflow for coverage threshold


6. **Проверки CI:**  
Merge разрешён только если:
- прошли все тесты (unit + e2e);
- покрытие ≥80%;
- линтеры без ошибок;
- PR одобрен ревьюером.

---

## G3 демонстрационные PR

Для проверки каждого пункта G3.x создай отдельную ветку и PR:
| Пункт | Пример ветки | Суть |
|-------|---------------|------|
| G3.0 | `chore/g3.0-contrib-rules` | добавлены эти правила |
| G3.4 | `break/g3.4-failing-unit` | упавший unit-тест блокирует merge |
| G3.5 | `break/g3.5-low-coverage` | покрытие <80%, merge запрещён |
| G3.6 | `break/g3.6-failing-e2e` | упавший e2e блокирует merge |
| G3.8 | `break/g3.8-lint-fail` | ошибка линтера блокирует merge |
